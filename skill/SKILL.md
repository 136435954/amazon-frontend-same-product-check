# 亚马逊前台同款占比验证

一条流水线：`读表 → 定站点 → 设邮编 → 逐词搜索框检索 → 抓前 50 位 → 判广告位 → 下图 → 判同款 → 出 CSV`。

## 输入：每次都要用户给，缺一不可

开跑前凑齐下面三样，缺哪样就问哪样，**一律不要自己猜、不要默认美国、不要沿用别的品类的口径**：

| 输入 | 说明 | 缺失时 |
|---|---|---|
| **站点** | 目标市场（US/UK/DE/JP/CA/AU/FR/ES/IT/SG/SE/PL/TR/IE/MX） | 问用户；不要从表名前缀推断后直接开跑 |
| **产品图** | 1–3 张本次基准产品图（正面主图为主，可补侧面/多件装/包装图） | 问用户；不要拿目录里随便一张图顶上 |
| **卖家精灵数据** | 含关键词列的 `.xlsx` 导出 | 问用户要文件路径 |

拿到三样后：站点用 `--site`、产品图用 `--target`（多张就空格并列）、xlsx 用 `--workbook` 显式传入。表名前缀只作**交叉校验**——前缀与用户给的站点不一致时，以用户给的为准并提示一句。

## 口径确认（每个新产品必做，两道关）

同款边界只能由用户定。**换产品（换基准图/换品类）就必须重新问一遍**，不许把上一个产品的口径套到新品类上。

### 第一关：看产品图，先出一版口径给用户确认

用户不需要自己想口径——你读产品图，把口径草案摆到他面前让他点头或改。流程：

1. 逐张读用户给的产品图（1–3 张），看清：品类是什么、决定"同款"的可见结构特征（外形轮廓、比例、关键部件、材质观感）、有几件/是否多件装。
2. 产出一版**口径草案**，必须写清四件事：
   - 本品类的核心识别特征（2–4 条，具体到形状/结构，不要"看起来像"这种空话）
   - 哪些近似品类算同款、哪些明确不算（各举 1–2 个具体例子）
   - 多件装：同型号多件装算不算、异款混装算不算
   - 颜色、尺寸、品牌、logo、包装、配件赠品怎么处理
3. 把草案发给用户，一句话问"按这个口径判定吗？要不要改哪一条"。用户点头或修正后才算通过。
4. 用户要求补充图片时（比如换个角度、补多件装图），让他再给 1–2 张，重新看一眼口径草案。
5. 草案通过后，把**用户最终确认的那版口径原文**记下来，第二关之后再写进 `work/judgments.json` 的 `_meta.rules`。

未通过第一关**不得开始任何抓取**。

### 第二关：前 5 词图像复核

1. 按用户口径跑**前 5 个词**（带图，不加 `--no-images`），生成每词 2 张 5×5 编号拼图（1–25 / 26–50）。
2. 拼图发给用户（图片用 `RichMediaCard`，不要用 Markdown 链接），说明编号规则：`#01` 即第 1 位，格内左上到右下。
3. 请用户对着图复核：口径是否成立、有没有漏掉的近似品类、有没有把不该算的算进来；用户要求改就改，改完再请他确认一次。
4. 用户确认或修正后，把**口径原文**写进 `work/judgments.json` 的 `_meta.rules`（原文照录，不要概括），并记下本次基准图文件名/ASIN 作为这条口径的适用对象。
5. 第二关没过（用户还没确认口径）之前，**不得启动批量**。

复用条件（三者同时满足才可沿用旧口径，且在开场复述一句让用户有机会改）：同一基准产品图（文件名或图哈希一致）+ 同一品类 + 同一站点。


## 不可谈判的口径

1. **站点由用户给，不默认美国、不猜测**。`--site` 必传；表名前缀与用户给的不一致时以用户为准。站点决定域名与邮编，猜错整份数据作废。
2. 第一个关键词之前必须把配送地址改成该站标准邮编，并确认页面顶部文案（如 `Los Angeles 90001`）。确认不到不开跑。
3. **每词必须凑满 50 个可见展示位**，不足就翻页续取；翻到第 5 页仍不足，按实际位数记录并在状态里注明。
4. 一个 ASIN 占多个位次就按位次重复计（广告位 + 自然位各算 1）。
5. 广告位计入范围：站内广告卡、品牌广告条整条及其条内**可见**瓦片、SB 网格广告的**可见**瓦片。轮播/货架里被 overflow 裁掉的隐藏瓦片既不算广告位也不算名额。
6. 搜索必须在前台搜索框里逐字输入 + 回车，禁止直接访问 `/s?k=` 取首页（会拿到另一套结果）。
7. 同款 = 同品类 + 同可见外形。品牌、颜色、logo、尺寸、包装不同都算同款；同一型号的多件装算 1 个位次，不同款混装不算。**换产品必须先读新图重出一版口径、等用户确认**，不许套用别的品类。
8. 红底填充（`FF0000`/`FFFF0000`）的关键词是已否定词，写 `否定词已跳过`，不搜索。
9. 同款占比 = 同款位次数 / 样本位次数 × 100，保留 1 位小数。

## 额度策略（重要）

| 阶段 | 消耗模型额度 | 说明 |
|---|---|---|
| 读表、定站点、扫基准图 | 否 | 本地 Python |
| ego 抓取 50 位 | 否 | 浏览器在本机跑，DOM 解析在 `page.evaluate` |
| 下载主图、拼 5×5 拼图 | 否 | 本地 |
| **判同款（看图）** | **是** | 唯一花钱的阶段 |
| 汇总写 CSV | 否 | 本地 |

2000 词 ≈ 10 万位 ≈ 4000 张拼图，逐张看不现实。默认策略：**先零成本全量抓取**（位次 + 广告位先落地），判定按 ASIN+图 hash 去重后**只判高价值子集**（200~300 词），其余同款列留空待补。全量判定需用户显式确认，或改接视觉 API。

## 执行

脚本：`scripts/amazon_frontend_check.py`（Python 3.10+，依赖 openpyxl、Pillow；ego-browser 不在 PATH 时脚本会自己找，也可设 `EGO_BROWSER`）。

```powershell
# 0) 看配置对不对（不联网、不花额度）：站点/基准图/主表都对上了再往下走
#    第一关：先读产品图，出一版口径草案给用户确认，未确认不得开始抓取
python scripts/amazon_frontend_check.py --workbook <卖家精灵.xlsx> --site US --target <产品图1> [<产品图2> <产品图3>] --print-config

# 1) 试点 5 词，出图（第二关：口径图像复核的素材，必须带图）
python scripts/amazon_frontend_check.py --workbook <xlsx> --site US --target <产品图...> --limit 5 --delay 10

# 1.5) 把 5×5 拼图发给用户复核口径 → 口径原文写进 work/judgments.json 的 _meta.rules
#      （第二关未通过不许进入下一步）

# 2) 全量抓取（零额度，分批挂后台，支持断点续跑）
python scripts/amazon_frontend_check.py --workbook <xlsx> --site US --target <产品图> --start 1 --limit 500 --no-images --delay 10

# 3) 判定子集：下图 + 拼图（仍不花额度）
python scripts/amazon_frontend_check.py --workbook <xlsx> --site US --target <产品图> --start 1 --limit 300 --skip-scrape

# 4) 看图判同款 → 写 work/judgments.json → 重跑出最终 CSV
python scripts/amazon_frontend_check.py --workbook <xlsx> --site US --target <产品图> --skip-scrape
```

常用参数：`--site US|UK|DE|JP|CA|AU|FR|ES|IT|SG|SE|PL|TR|IE|MX`、`--target 基准图`、`--profile "Profile 1"`（复用真实浏览器配置，必须建空间时传入）、`--top-n 50`、`--pages 5`、`--batch 30`、`--delay 12`。

产物：`amazon_analysis_result_top50.csv`（列：`关键词 | 翻译 | 验证状态 | 广告位数(前50名) | 前50名同款数量(含广告) | 同款占比 (%)`）、`work/scrape/<kw>.json`（每词 50 条明细）、`work/images/<kw>/<rank>_<asin>.jpg`、`work/review/*_sheet1|2.jpg`（5×5 编号拼图）、`work/judgments.json`。

## 判广告位（核心，别简化）

按 `references/dom-recipes.md` 的选择器实现，主判据是 `[aria-label*="Sponsored" i]`；品牌条与 SB 网格靠 `_c2Itd_` 容器与 `_c2Itd_ad-feedback-text-desktop` 标记；轮播瓦片只算可见的。

判"0 广告"之前，先跑证据链（`sp-sponsored-result`、`cel_widget_id`、`.AdHolder`、aria 计数）；任一项不为 0 却判 0，就是漏判，回去核对版式。

站点与邮编见 `references/marketplaces.md`（15 站，含爱尔兰用 co.uk 域名、瑞典/波兰/土耳其等）。

## 风控

- 命中 `/checkpoint/`、`/errors/validateCaptcha`、页面出现 `I am human` / `unusual browser activity` → 该词记 `captcha`，整批早停，冷却 600s 后重试一次。
- **绝不代点、绝不破解人机校验**。连续两次命中就交给用户处理，并在 CSV 里写 `风控未完成`。
- 词间默认 12s 保守节流；同一会话内不要并行搜索。

## 踩坑

- ego 空间可能被复用：`profileId` 只在**创建**空间时生效，对已存在空间传会报 `profileId only applies when creating a new task space`。要么先复用、要么换新名字。
- PowerShell 无 heredoc，长 JS 写 `.mjs` 再 `ego-browser nodejs -e "await import('file:///…')"`。脚本内不能用 `window/document`，必须放 `page.evaluate()`。
- 滚动后顶部搜索框可能不可见，点击会报 `element is not visible in the viewport`；搜索前先 `window.scrollTo(0,0)`。
- 广告数与结果数逐次波动（亚马逊按请求动态下发），同一词两次跑出 11 和 19 属正常；跨词比较要用同一批跑出来的数。
